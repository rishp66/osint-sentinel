# OSINT Sentinel — Multi-Agent Threat Intelligence Platform

A full-stack OSINT aggregation platform that queries **14+ intelligence sources in parallel** and synthesizes results using an **LLM-powered agent** (Gemma 4 31B via Lightning.ai) into an actionable threat brief and full markdown intelligence report.

## Architecture

```
┌─────────────────────────────────────────────────┐
│              React + Vite Frontend               │
│     (Search bar → Live progress → Dashboard)     │
└──────────────────────┬──────────────────────────┘
                       │ REST API (Vite proxy)
┌──────────────────────▼──────────────────────────┐
│              FastAPI Backend (port 8000)          │
│                                                   │
│  POST /scan                                       │
│  ┌─────────────────────────────────────────────┐  │
│  │  ThreadPoolExecutor — parallel OSINT fetch  │  │
│  │                                             │  │
│  │  WHOIS   VirusTotal  AbuseIPDB  Shodan      │  │
│  │  AlienVault OTX      IPInfo     DNS         │  │
│  └──────────────────┬──────────────────────────┘  │
│                     │ trim → fewer tokens          │
│  ┌──────────────────▼──────────────────────────┐  │
│  │  Lightning.ai — Gemma 4 31B                 │  │
│  │  ├─ Synthesis agent  → risk score + brief   │  │
│  │  └─ Report agent     → full markdown report │  │
│  └─────────────────────────────────────────────┘  │
│                                                   │
│  In-memory TTL cache (300 s)                      │
└──────────────────────────────────────────────────┘
```

## Features

- **Parallel OSINT queries** — all sources fetched concurrently via `ThreadPoolExecutor`, with an 18 s global timeout (slow sources are abandoned, not awaited)
- **Single DNS pre-resolution** — domain resolved once and reused by AbuseIPDB, Shodan, and IPInfo
- **LLM synthesis** — risk score (0–100), risk level (LOW / MEDIUM / HIGH / CRITICAL), and a threat brief
- **Full intelligence report** — structured markdown report generated by the agent with CVE callouts, recommendations, and IOCs
- **Progress bar** — asymptotic loading curve in the UI so users know the scan is running
- **Graceful degradation** — if LLM times out, raw source data is still returned with a fallback message
- **Source error handling** — failed or empty sources show "No information could be found for this source at this time." instead of raw errors
- **In-memory cache** — repeat scans within 5 minutes return instantly

## OSINT Sources

Sentinel routes each query to the sources that can actually answer it based on the indicator type (IP, domain, URL, file hash, or CVE).

| Source | Data Provided | Applies To | API Key |
|--------|--------------|------------|---------|
| WHOIS (`python-whois`) | Registrar, dates, nameservers, org | domain | No |
| VirusTotal | Malware detections, categories, reputation | ip, domain, url, hash | Free tier |
| AbuseIPDB | Abuse confidence score, reports, ISP | ip, domain, url | Free tier |
| Shodan | Open ports, services, CVEs, ASN | ip, domain, url | Free tier |
| AlienVault OTX | Threat pulses, malware families, passive DNS | ip, domain, url | Free |
| IPinfo | Geolocation, ASN, org, hostname | ip, domain, url | Free tier |
| GreyNoise (Community) | Mass-scanner classification, RIOT common-service flag | ip | No |
| urlscan.io | Historical URL scans, verdicts, screenshots | ip, domain, url | Free tier |
| Hybrid Analysis | Falcon Sandbox lookup — verdict, threat score, family | hash | Free (vetted) |
| RDAP (`ipwhois`) | ASN, CIDR, network owner, abuse contacts (all RIRs) | ip | No |
| CIRCL Vulnerability-Lookup | CVE details — CVSS, summary, references | cve | No |
| ThreatFox (abuse.ch) | IOC → malware family mapping | ip, domain, url, hash | Free |
| URLhaus (abuse.ch) | Malware URL distribution tracking | ip, domain, url, hash | Free |
| MalwareBazaar (abuse.ch) | Malware sample metadata by hash | hash | Free |
| Pulsedive | Risk scoring and enrichment across indicator types | ip, domain, url, hash | Optional |

> **abuse.ch note:** ThreatFox, URLhaus, and MalwareBazaar all share a single abuse.ch account — one key unlocks all three (`ABUSECH_AUTH_KEY`).

## Quick Start

### 1. Clone & install backend

```bash
cd backend
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Configure environment

```bash
cp .env.example .env
# Edit .env and fill in:
#   LIGHTNING_API_KEY   — from lightning.ai (required for LLM synthesis)
#   VIRUSTOTAL_API_KEY
#   ABUSEIPDB_API_KEY
#   SHODAN_API_KEY
#   OTX_API_KEY
#   IPINFO_TOKEN
```

### 3. Install & run frontend

```bash
cd frontend
npm install
```

### 4. Launch both servers

```bash
# Terminal 1 — Backend
cd backend
uvicorn main:app --reload --port 8000

# Terminal 2 — Frontend
cd frontend
npm run dev
```

Open **http://localhost:5173** in your browser.

The frontend proxies `/scan` and `/health` requests through Vite to the backend, so no CORS issues in development.

### 5. Verify

```bash
curl http://localhost:8000/health
# {"status": "ok"}
```

## Deploying to a Domain

The app is split into two deployable units. The recommended layout is:

- **Backend** on its own host (Fly.io, Render, Railway, a VM behind nginx, etc.) at e.g. `https://api.sentinel.example.com`. Set:
  - `CORS_ORIGINS=https://sentinel.example.com`
  - `TRUST_PROXY_HEADERS=true` (only if the platform terminates TLS in front of you and forwards `X-Forwarded-For`)
  - `DEBUG=false`
- **Frontend** as a static build (`npm run build`) served from a CDN / static host (Vercel, Netlify, Cloudflare Pages, S3+CloudFront). Set the build-time env:
  - `VITE_API_BASE_URL=https://api.sentinel.example.com`

If you'd rather serve everything from one origin, put the backend behind a reverse proxy that maps `/scan` and `/health` to the API and `/` to the static build — then leave `VITE_API_BASE_URL` empty and `CORS_ORIGINS` unset.
